Objective

In this lab, you will build the complete STM32 embedded development environment from scratch on your laptop. You will install STMicroelectronics' official code-generation tool (STM32CubeMX), the ARM compiler and programmer suite (STM32CubeCLT), and a fully configured Visual Studio Code workspace. Using these tools, you will generate a HAL-based firmware project for the NUCLEO-L496ZG-P development board, write a simple verification program that blinks an LED and streams data over a UART serial connection, and confirm end-to-end operation by observing both the physical LED and a serial terminal on your laptop.

By the end of this lab you will be able to: create a new STM32 project from a board template in STM32CubeMX, configure on-chip peripherals through the graphical Pinout view, generate a CMake-based project, build and flash firmware entirely within VS Code, and interpret live serial output from the target board.

Required Materials

  • NUCLEO-L496ZG-P Development Board
  • USB Type-A to Micro-USB Cable (for the on-board ST-LINK programmer)
  • Laptop running Windows 10 or Windows 11 (64-bit)
  • Internet connection (for downloading tools and firmware packages)

Background

The STM32 Ecosystem

STMicroelectronics produces one of the most widely used families of 32-bit microcontrollers in industry: the STM32 series. These devices are built on ARM Cortex-M cores and span an enormous range of performance and power profiles. To help developers get up and running quickly, ST provides a tightly integrated software ecosystem consisting of three major components you will use throughout this course:

  • STM32CubeMX – A graphical tool that lets you select a target device or development board, configure its pins and peripherals through a visual interface, set up clocks, and then automatically generate a ready-to-compile C project with all of the necessary initialization code already written for you.
  • STM32CubeCLT (Command Line Tools) – A self-contained installer that delivers the ARM cross-compiler (arm-none-eabi-gcc), the CMake build system, the Ninja build runner, the ST-LINK GDB server (for on-chip debugging), and the STM32CubeProgrammer CLI (for flashing firmware). Every tool required to build and deploy STM32 firmware is bundled in this single package.
  • STM32 VS Code Extension – An official ST extension for Visual Studio Code that ties CubeMX and CubeCLT together. It auto-detects CubeMX project files, drives the CMake build through a single button click, and can flash or debug the board directly from the editor.

The NUCLEO-L496ZG-P Development Board

The NUCLEO-L496ZG-P is a Nucleo-144 format evaluation board built around the STM32L496ZGT6P microcontroller. Key hardware facts you will rely on in this lab:

  • Core: ARM Cortex-M4 with FPU, running up to 80 MHz.
  • Memory: 1 MB Flash, 320 KB SRAM.
  • On-board ST-LINK/V3E: An integrated programmer/debugger that connects to your laptop over a single Micro-USB cable. It appears on your PC as a virtual COM port (for serial output) and as a programmable debug interface (for flashing and stepping through code) — no external programmer is needed.
  • User LEDs: Three user-controllable LEDs — LD1 (green), LD2 (blue), and LD3 (red) — accessible through GPIO pins that CubeMX will name and configure for you.
  • User Push-Button (B1): A tactile button connected to PC13 with an external pull-up resistor.
  • Virtual COM Port (VCP): USART3 (pins PD8/PD9) is wired directly to the ST-LINK, so data you transmit with HAL_UART_Transmit() appears in a serial terminal on your laptop without any additional hardware.

Board Orientation Note: The NUCLEO-L496ZG-P has two USB connectors. The Micro-USB port labeled "USB ST-LINK" (CN1) is the one used for programming and the virtual COM port. The second USB connector is for the STM32's own USB peripheral and is not used in this lab. Always plug the ST-LINK port into your laptop.

Hardware Abstraction Layer (HAL)

The STM32 HAL (Hardware Abstraction Layer) is a C library generated and maintained by STMicroelectronics. It wraps every on-chip peripheral — GPIOs, UARTs, SPI buses, DMA controllers, timers, and more — behind a consistent, device-independent API. This means that code written with HAL_GPIO_TogglePin() will compile and behave correctly on an L496, an F4, an H7, or any other STM32 device with only minor project-level changes.

CubeMX generates the HAL initialization code automatically based on your peripheral configuration. Your job as the application developer is to call the HAL functions in the USER CODE sections of main.c. These specially marked sections are preserved every time you regenerate from CubeMX, so you never lose your application code when you change a peripheral setting.

CMake Build System

CMake is an industry-standard, cross-platform build system generator. When you select CMake as the toolchain in CubeMX's Project Manager, CubeMX outputs a CMakeLists.txt that describes all source files, include paths, compiler flags, and linker scripts for your project. The STM32 VS Code Extension and the cmake-tools extension then read this file to drive the actual compilation with arm-none-eabi-gcc. You do not need to write or edit the CMakeLists.txt by hand.

Procedure

1. Create an STMicroelectronics Account

Downloading STM32CubeMX and STM32CubeCLT requires a free ST account. If you already have one, skip to Step 2.

  1. Open a web browser and go to https://www.st.com.
  2. Click the person icon (👤) in the top-right corner of the page, then click Create an account.
  3. Fill in your name, email address, and a password. Use your university email address for academic access. Accept the terms and conditions and click Create account.
  4. Check your email for a verification link from STMicroelectronics and click it to activate your account.
  5. Return to https://www.st.com and sign in with your new credentials before proceeding. The download buttons in the next steps will not function if you are not signed in.

2. Download and Install STM32CubeMX

  1. Navigate to the STM32CubeMX product page: https://www.st.com/en/development-tools/stm32cubemx.html
  2. Scroll down to the Get Software section and click the Get latest button next to the Windows installer. You will be presented with a license agreement; read it, check the acceptance box, and click Download.
  3. Once the download completes, locate the file en.SetupSTM32CubeMX-*.exe in your Downloads folder. Double-click it to launch the installer.
  4. If Windows Defender SmartScreen displays a warning, click More info and then Run anyway. This warning appears because the installer is not code-signed by a known Windows publisher; it is safe to proceed.
  5. The STM32CubeMX Setup Wizard will open. Click Next on the welcome screen.
  6. Read the license agreement, select I accept the terms of this license agreement, and click Next.
  7. Accept the default installation directory (C:\ST\STM32CubeMX). Click Next, then Install. The installation will take about one minute.
  8. When the installer finishes, leave Launch STM32CubeMX unchecked for now and click Finish.

3. Download and Install STM32CubeCLT

STM32CubeCLT is the collection of command-line tools that performs the actual work of compiling, linking, and flashing your firmware. It must be installed before the VS Code extension can function.

  1. Navigate to the STM32CubeCLT product page: https://www.st.com/en/development-tools/stm32cubeclt.html
  2. In the Get Software section, click Get latest next to the Windows installer. Accept the license agreement and download.
  3. Locate the file en.STM32CubeCLT_*.exe in your Downloads folder. Right-click it and select Run as administrator. Administrator privileges are required so the installer can add the ST-LINK USB driver to Windows.
  4. Click through the setup wizard. Accept the license agreement and use the default installation path, which will be something like C:\ST\STM32CubeCLT_1.x.x\. Make note of this exact path — you will need to enter it in VS Code later.
  5. When prompted about installing the ST-LINK USB Driver, click Yes or Install. This driver is what allows Windows to recognize your NUCLEO board as both a programming interface and a virtual COM port.
  6. Complete the installation and click Finish. Do not reboot yet if prompted; you can reboot after all tools are installed.

What was installed: Inside C:\ST\STM32CubeCLT_1.x.x\ you will now find sub-folders including GNU-tools-for-STM32\ (containing arm-none-eabi-gcc.exe), CMake\, Ninja\, STLink-gdb-server\, and STM32CubeProgrammer\. You do not need to configure these paths manually; the STM32 VS Code Extension reads them from the parent directory.

4. Install Visual Studio Code

  1. Go to https://code.visualstudio.com/ and click the large blue Download for Windows button. This downloads the System Installer (VSCodeSetup-x64-*.exe).
  2. Run the installer. When you reach the Select Additional Tasks screen, check all of the following boxes:
    • Add "Open with Code" action to Windows Explorer file context menu
    • Add "Open with Code" action to Windows Explorer directory context menu
    • Register Code as an editor for supported file types
    • Add to PATH (requires shell restart) — this is the most important one
  3. Click Next, then Install. When the installer finishes, leave Launch Visual Studio Code checked and click Finish.
  4. VS Code will open for the first time and may show a welcome tab and theme selection prompts. Close those for now; you will configure it in the next step.

5. Install Required VS Code Extensions

Extensions add language support, build system integration, and hardware debug capability to VS Code. You need to install four extensions. All of them are installed the same way: open the Extensions sidebar by pressing Ctrl+Shift+X (or clicking the four-square icon on the left Activity Bar), type the extension name in the search box, and click Install on the correct result.

5a. C/C++ Extension Pack

  1. In the Extensions search box, type: C/C++ Extension Pack
  2. Find the result published by Microsoft (identifier: ms-vscode.cpptools-extension-pack). Click Install. This pack installs the C/C++ IntelliSense engine, the CMake language extension, and the CMake Tools build-system driver all at once.

5b. STM32 VS Code Extension

  1. In the Extensions search box, type: STM32 VS Code Extension
  2. Find the result published by stmicroelectronics (identifier: stmicroelectronics.stm32-vscode-extension). Click Install. This is ST's official extension that provides build, flash, and debug commands integrated directly with your CubeMX project and CubeCLT tools.
  3. After the extension installs, you will see a new STM32 icon (an ST logo) appear in the left Activity Bar of VS Code.

5c. Cortex-Debug

  1. In the Extensions search box, type: Cortex-Debug
  2. Find the result published by marus25 (identifier: marus25.cortex-debug). Click Install. Cortex-Debug provides the low-level JTAG/SWD debug adapter support that lets VS Code connect to the STM32's debug port through the on-board ST-LINK.

5d. Serial Monitor

  1. In the Extensions search box, type: Serial Monitor
  2. Find the result published by Microsoft (identifier: ms-vscode.vscode-serial-monitor). Click Install. This extension lets you open a serial terminal to your board's virtual COM port directly inside VS Code without needing an external program like PuTTY.

5e. Configure the STM32 Extension with the CubeCLT Path

The STM32 extension must know where CubeCLT was installed so it can find the compiler and programmer.

  1. In VS Code, open the Settings editor by pressing Ctrl+, (Ctrl and comma).
  2. In the Settings search bar at the top, type: STM32 cubeclt
  3. You will see an entry labeled STM32VSCodeExtension: Cube CLT with a text field below it. Click Edit in settings.json or simply type the path directly into the field: 
    C:\ST\STM32CubeCLT_1.x.x
    Replace 1.x.x with the exact version number in your installation folder. For example, if the folder is named STM32CubeCLT_1.16.0, enter C:\ST\STM32CubeCLT_1.16.0.
  4. Press Ctrl+S to save the settings. Close the Settings tab.

Tip: To find the exact folder name, open File Explorer and navigate to C:\ST\. You will see a folder whose name begins with STM32CubeCLT_. Copy the full folder name exactly as it appears and paste it after C:\ST\ in the VS Code settings field.

6. Install the STM32CubeL4 Firmware Package

STM32CubeMX needs the device-specific HAL library (the STM32CubeL4 firmware package) to generate correct driver code for the L496 microcontroller. You will install it now through CubeMX's built-in package manager.

  1. Launch STM32CubeMX from the Start menu or the desktop shortcut.
  2. When the CubeMX home screen loads, click the Help menu in the top menu bar and select Manage embedded software packages. The Embedded Software Packages Manager window will open.
  3. In the list on the left, click STM32Cube MCU Packages to expand it, then click on STM32L4.
  4. On the right side of the window, you will see a list of available STM32CubeL4 package versions. Click the checkbox next to the latest version (the one at the top of the list, e.g., STM32Cube_FW_L4_V1.x.x).
  5. Click the Install Now button at the bottom of the window. CubeMX will download the package from ST's servers. This may take several minutes depending on your connection speed, as the package is several hundred megabytes.
  6. A license agreement prompt will appear. Read it, accept it, and click Finish.
  7. When the installation completes, the version row will show a green checkmark icon. Close the Embedded Software Packages Manager by clicking the X button.

Why is this necessary? The STM32CubeL4 firmware package contains the HAL source files (stm32l4xx_hal_gpio.c, stm32l4xx_hal_uart.c, etc.) and the CMSIS startup files that CubeMX copies into your project. Without this package installed, CubeMX cannot generate a complete, compilable project for L-series devices.

7. Create a New STM32CubeMX Project for the NUCLEO-L496ZG-P

  1. In STM32CubeMX, click ACCESS TO BOARD SELECTOR on the home screen. (If CubeMX is already open with a project, go to File → New Project and then click the Board Selector tab at the top of the dialog.)
  2. The Board Selector view will open. In the Commercial Part Number search field on the left, type exactly: 
    NUCLEO-L496ZG-P
  3. A single result will appear in the board list on the right. Click on the board image or the row to select it. You will see the board description, documentation links, and a photo of the NUCLEO-L496ZG-P. Confirm it shows STM32L496ZGTxP as the MCU.
  4. Click the Start Project button in the top-right area of the window (it may also be labeled Create Project).
  5. A dialog box will appear asking: "Initialize all peripherals with their default Mode?"
    Click Yes. This is a critical step — it configures the board's built-in LEDs, user button, and ST-LINK UART connection automatically, matching the physical hardware connections on the PCB.
  6. CubeMX will switch to the Pinout & Configuration view. You will see a rendered die image of the STM32L496 with colored pins indicating which functions are active. Green pins are GPIO outputs (LEDs), a yellow pin is the button input, and blue pins are the USART3 TX and RX lines.

8. Verify Peripheral Configuration in STM32CubeMX

With the board initialized, take a moment to verify the key peripherals are configured correctly before generating code. The board initialization handled most of this automatically.

8a. Verify the User LEDs

  1. In the Pinout view, locate and click on the GPIO pins that are colored green and labeled LD1, LD2, and LD3. They will each show a mode of GPIO_Output. This is correct.
  2. On the left panel under Categories, click System Core and then GPIO. You will see a table listing all configured GPIO pins. Confirm that entries for LD1, LD2, and LD3 exist with output level set to Low and GPIO mode set to Output Push Pull. These are your three user LEDs.
  3. Note the User Label column for each LED pin. CubeMX will use these labels (e.g., LD1, LD2, LD3) to generate convenience macros in main.h. Your application code will use these macros — for example, LD1_Pin and LD1_GPIO_Port — rather than raw register names. This makes your code readable and portable.

8b. Verify USART3

  1. On the left panel under Categories, click Connectivity and then USART3.
  2. Confirm the following settings are present (they should be set by the board default):
    • Mode: Asynchronous
    • Baud Rate: 115200 Bits/s
    • Word Length: 8 Bits
    • Parity: None
    • Stop Bits: 1
    These settings match the ST-LINK virtual COM port's default configuration and must not be changed.

8c. Review the Clock Configuration (Optional but Recommended)

  1. Click the Clock Configuration tab at the top of the CubeMX window.
  2. You will see a block diagram of the STM32L496's clock tree. The board initialization will have configured a clock source and PLL settings. Verify that HCLK (the main CPU and bus clock) shows a value greater than 4 MHz. A value of 80 MHz is the maximum for the L496 and is ideal for this lab.
  3. If HCLK is at a low value (e.g., 4 MHz), consult your instructor. The board default should configure a higher value, but firmware behavior for USART baud rate depends on the actual clock frequency.

12. Write the Verification Firmware

Now you will modify main.c to add a blinking LED and a UART status stream. Every edit you make must be placed inside the designated /* USER CODE BEGIN */ and /* USER CODE END */ markers. Code outside those markers is owned by CubeMX and will be deleted the next time you regenerate.

  1. In the VS Code Explorer panel (left sidebar), expand Core → Src and click on main.c to open it.
  2. Scroll down to find the section that reads: 
    /* USER CODE BEGIN Includes */

/* USER CODE END Includes */
    Place your cursor on the blank line between the two markers and add the following two include statements: 
    /* USER CODE BEGIN Includes */
#include <stdio.h>
#include <string.h>
/* USER CODE END Includes */
    These standard C headers give you access to snprintf() (for formatting strings) and strlen() (for measuring string length), both needed for UART output.
  3. Scroll further down to find the USER CODE BEGIN 0 section, which appears just before the int main(void) line. Add these two variable declarations: 
    /* USER CODE BEGIN 0 */
static uint32_t seconds_elapsed = 0;
static char     uart_buf[80];
/* USER CODE END 0 */
    seconds_elapsed will count how many seconds the board has been running, and uart_buf is the buffer into which formatted messages will be written before transmission.
  4. Inside main(), scroll past all of the peripheral initialization calls (e.g., MX_GPIO_Init(), MX_USART3_UART_Init()) until you find the USER CODE BEGIN 2 section. Add the startup message transmission here: 
    /* USER CODE BEGIN 2 */
const char *startup_msg =
    "\r\n==============================\r\n"
    "  ECGR-4101 Lab 1 Verification \r\n"
    "  NUCLEO-L496ZG-P Ready        \r\n"
    "==============================\r\n";
HAL_UART_Transmit(&huart3, (uint8_t *)startup_msg,
                  strlen(startup_msg), HAL_MAX_DELAY);
/* USER CODE END 2 */
    huart3 is the HAL UART handle generated by CubeMX for USART3 (the ST-LINK virtual COM port). HAL_MAX_DELAY means the call will block until the transmission is fully complete before returning.
  5. Scroll further down into the infinite loop. Find the section that reads: 
      /* USER CODE BEGIN WHILE */
  while (1)
  {
    /* USER CODE END WHILE */

    /* USER CODE BEGIN 3 */
  }
  /* USER CODE END 3 */
    Replace the contents of the loop (between WHILE and END WHILE) with the following application logic. Your completed loop section should look exactly like this: 
      /* USER CODE BEGIN WHILE */
  while (1)
  {
    /* Toggle the green user LED (LD1) */
    HAL_GPIO_TogglePin(LD1_GPIO_Port, LD1_Pin);

    /* Format a status message and send it over USART3 */
    int msg_len = snprintf(uart_buf, sizeof(uart_buf),
                           "Lab 1 OK  |  t = %4lu s  |  LD1 = %s\r\n",
                           seconds_elapsed,
                           HAL_GPIO_ReadPin(LD1_GPIO_Port, LD1_Pin) ? "ON " : "OFF");
    HAL_UART_Transmit(&huart3, (uint8_t *)uart_buf,
                      (uint16_t)msg_len, HAL_MAX_DELAY);

    seconds_elapsed++;

    /* Wait 1000 ms before the next iteration */
    HAL_Delay(1000);
    /* USER CODE END WHILE */

    /* USER CODE BEGIN 3 */
  }
  /* USER CODE END 3 */
  6. Press Ctrl+S to save main.c.

Code explanation:

  • HAL_GPIO_TogglePin(LD1_GPIO_Port, LD1_Pin) — Reads the current output latch of the LD1 pin and writes the opposite value, toggling the LED between on and off with each call. The macros LD1_GPIO_Port and LD1_Pin are defined in the generated main.h — you can Ctrl+Click on them to verify the actual port and pin number.
  • snprintf(uart_buf, sizeof(uart_buf), ...) — Safely formats a string into uart_buf without risking a buffer overflow. It returns the number of characters written, which we store in msg_len and pass to HAL_UART_Transmit() so the HAL knows exactly how many bytes to send.
  • HAL_Delay(1000) — Puts the processor into a busy-wait loop for exactly 1000 milliseconds, producing a 1 Hz LED toggle rate and one UART message per second.

13. Rebuild the Project

  1. Click the Build button in the STM32 extension panel, or press Ctrl+Shift+B.
  2. Confirm the build completes with 0 errors. If you see errors, carefully compare your code to the snippets above, paying close attention to:
    • Correct placement of code inside the USER CODE markers (not before BEGIN or after END).
    • Correct UART handle name: use huart3, not huart1 or husart3.
    • The & operator before huart3 in HAL_UART_Transmit() — you are passing a pointer to the handle, not the handle itself.
    • The correct macro names: Ctrl+Click on LD1_Pin to navigate to its definition in main.h and confirm the macro exists.

14. Connect the NUCLEO-L496ZG-P and Install the Driver

  1. Plug one end of your Micro-USB cable into the port on the NUCLEO board labeled USB ST-LINK (CN1). This connector is near the ST-LINK chip at the top edge of the board (the portion of the board above the thin blue line separating the ST-LINK section from the target MCU section).
  2. Plug the other end of the cable into any USB port on your laptop.
  3. The green power LED (LD3 PWR, not to be confused with the user LD3) near the USB connector on the board should illuminate immediately, confirming the board is receiving power.
  4. Windows will detect the new device. A notification may appear saying "Setting up a device." Wait until this completes. Because you installed STM32CubeCLT earlier (which included the ST-LINK driver), the board should be recognized without any additional driver installation.
  5. To confirm the driver is installed correctly, right-click the Start button and select Device Manager. Expand the Ports (COM & LPT) section. You should see an entry labeled STMicroelectronics STLink Virtual COM Port (COMx) where x is a number such as 3, 5, or 7. Make note of this COM port number — you will need it for the serial terminal in Step 16.
  6. In Device Manager, also expand Universal Serial Bus devices (or Other devices). You should see ST-LINK Debug listed without a yellow warning icon. If you see a yellow exclamation mark, the ST-LINK driver did not install correctly. In that case, right-click the entry, select Update driver → Browse my computer → Let me pick, and navigate to C:\ST\STM32CubeCLT_1.x.x\STLink-gdb-server\bin\ to locate and install the driver manually.

15. Flash the Firmware to the Board

  1. In VS Code's STM32 extension panel, locate the Flash section. Click the Flash button (the lightning bolt icon). Alternatively, open the Command Palette with Ctrl+Shift+P, type STM32: Flash, and press Enter.
  2. The STM32 extension will invoke the STM32CubeProgrammer CLI to communicate with the ST-LINK on your board. The Terminal panel will display progress similar to: 
          -------------------------------------------------------------------
                        STM32CubeProgrammer v2.x.x
      -------------------------------------------------------------------

16. Verify Output with the Serial Monitor

With the firmware running and LD1 blinking, the final step is to open a serial terminal and read the UART messages the board is sending. You will use the Serial Monitor extension you installed earlier.

  1. In VS Code, open the Command Palette (Ctrl+Shift+P) and type Serial Monitor: Focus on Serial Monitor View. Press Enter. A Serial Monitor panel will appear at the bottom of VS Code.
  2. In the Serial Monitor panel's toolbar, click the Port dropdown and select the COM port you identified in Step 14.5 (e.g., COM5).
  3. Click the Baud rate dropdown and select 115200.
  4. Click the Start Monitoring (play ▶) button in the Serial Monitor toolbar. The monitor will open the port and begin listening.
  5. Within one second, you should see the startup banner appear in the monitor:

  6. If you do not see any output:
    • Verify you have selected the correct COM port. In Device Manager under Ports (COM & LPT), the ST-LINK Virtual COM port will disappear when you unplug the board and reappear when you plug it back in — use this to identify the correct port number unambiguously.
    • Confirm the baud rate is 115200. Mismatched baud rates produce garbage characters or no output at all.

17. Checkpoint: Exploring the Generated HAL Code

Before finishing the lab, spend a few minutes exploring the code CubeMX generated on your behalf. Understanding this structure is foundational to all future labs in this course.

  1. In the VS Code Explorer, open Core → Inc → main.h. Scroll to the section labeled Exported pins or search for the text LD1_Pin. You will see the actual hardware pin assignment, for example: 
    #define LD1_Pin          GPIO_PIN_4
#define LD1_GPIO_Port    GPIOD
    This confirms that the green LED is connected to pin PD4 on the L496. The generated macros insulate your application code from these hardware details.
  2. Open Core → Src → stm32l4xx_hal_msp.c. This file contains the MSP (MCU Support Package) functions — low-level peripheral initialization callbacks (enabling GPIO clocks, configuring DMA channels, etc.) that CubeMX generates and maintains for you. You should recognize the GPIO and UART clock enables inside these functions.
  3. Open Drivers → STM32L4xx_HAL_Driver → Src → stm32l4xx_hal_gpio.c. Browse to the HAL_GPIO_TogglePin() function definition. Observe how the HAL translates a high-level function call into a single write to the GPIO port's BSRR (Bit Set/Reset Register) — this is the kind of hardware detail the HAL abstracts away from your application code.
